可复现分析脚本的最小目录

一份分析从笔记本长成项目时，用固定目录把原始数据、样本、估计和输出分开，让别人能重跑主结果。

    笔记本适合探索。一旦某个表要进论文，就把它从笔记本里拆出来，放进能从头跑到尾的目录。目录不需要大，需要边界清楚。

    1. 四个目录就够开始

    project/
  data/raw/        原始文件，只读
  data/interim/    清洗后的分析样本
  src/             脚本，按编号顺序运行
  output/          表和图，脚本可覆盖

    data/raw/ 里的文件不由脚本改写。清洗结果写到 data/interim/。表和图只出现在 output/，不要散落在桌面或下载文件夹。

    2. 脚本按依赖编号

    • src/00_sample.py：读 raw，写分析样本，并打印行数；
    • src/01_main.py：读 interim，写主表；
    • src/02_figure.py：读同一份 interim，写图。

    后一个脚本不读取前一个脚本的内存，只读取它落盘的文件。这样中断之后可以从断点重跑，也不必猜“是不是还开着那个笔记本”。

    3. 路径和版本写在入口

    每个脚本开头固定三件事：项目根路径、输入文件名、输出文件名。依赖版本写进 requirements.txt，不要只留在本机环境里。随机过程要设种子，并在输出旁注明种子值。

    数据若不能公开，至少在 README 里写：文件从哪来、哪一天下载、哪一个字段被用到。别人没有这份文件时，应能判断缺的是数据，而不是脚本。

    4. 什么时候才加配置文件

    规格少于三个、路径少于五个时，不必上配置框架。把参数放在 01_main.py 顶部的常量里即可。规格变多、或同一脚本要换数据集时，再把常量收进一个小的配置文件。提前抽象，只会让重跑主结果多一层寻找。

    5. 完成的定义

    从空的 output/ 出发，按编号跑完脚本，主表的样本量和系数与论文一致。做不到这一步，目录还只是文件夹，不是可复现的分析。

    6. 一个数怎么穿过目录

    原始文件里有一列 score。00_sample.py 只做两件事：丢掉缺失，把分析样本写到 data/interim/sample.csv，并打印行数。01_main.py 只读这份样本，计算均值，写到 output/mean.txt。

    若原始 100 行、缺失 5 行，interim 应是 95 行，输出里的均值只在这 95 行上计算。有人改了笔记本里的过滤却没有重跑 00_sample.py 时，mean.txt 仍是旧的 95 行结果。目录的作用就是让这种不一致变成“文件对不上”，而不是藏在一次交互式运行里。
