AI Agent 架构模式：从单代理到多代理协作

梳理 Agent 系统常见架构范式，解释规划、执行、记忆与工具调用的解耦设计。

    1. Agent 和普通问答系统的区别

    普通问答系统输出一段文本；Agent 需要完成任务。
    这要求系统具备“目标分解 -> 工具执行 -> 状态更新 -> 结果验证”的闭环。

    2. 常见架构模式

    1. ReAct：推理与动作交替。
    2. Plan-and-Execute：先全局规划，再逐步执行。
    3. Router + Specialists：按任务路由到专长子代理。
    4. Supervisor 多代理：主代理调度多个执行代理。

    3. 设计原则

    1. 把推理层与执行层解耦。
    2. 把短期上下文与长期记忆解耦。
    3. 把工具权限按最小可用原则收敛。

    4. Python 任务循环示例

    state = {"goal": user_goal, "memory": [], "done": False}

while not state["done"]:
    plan = planner(state)
    action = executor(plan)
    obs = tool_runtime(action)
    state = updater(state, plan, action, obs)
    state["done"] = checker(state)

    5. 关键风险

    1. 无限循环与无效重试。
    2. 错误工具选择导致级联失败。
    3. 记忆污染（把错误中间结论写入长期记忆）。

    6. 实务建议

    1. 每个步骤都做结构化日志。
    2. 高风险操作必须人类确认。
    3. 为每类任务设“终止条件 + 回退策略”。

    Agent 架构优劣的分水岭，不在“会不会调用工具”，而在“失败时如何可控收敛”。

    6. 一步闭环里有什么

    一步包含四件事：当前目标、选中的工具、工具返回的状态、对这个状态的检查。检查失败就停止或回退，而不是自动再调用同一个工具。

    例如目标是“算出两个数的和”。工具返回了空字符串。检查发现结果不是数字，于是停止，并把空返回记为失败。若没有检查，下一步会把空字符串送进后续计算，错误会看起来像模型“不会算术”。架构要记录的是哪一步的状态不合格，而不是只保留最后一段自然语言。
